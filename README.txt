SOULVAULT — ระบบทดลองเล่นออนไลน์ 2 คน (Realtime Prototype)

ไฟล์ภายใน
- index.html, style.css, app.js: ไฟล์เว็บไซต์ SOULVAULT ชุดล่าสุดที่ได้รับมา
- online-simulator.js: ระบบสร้างห้องและซิงก์เกมแบบเรียลไทม์

วิธีติดตั้ง
1. สร้างโปรเจกต์ใหม่ที่ https://supabase.com/ แล้วรอให้โปรเจกต์พร้อมใช้งาน
2. ใน Supabase เปิด Project Settings / API หรือหน้า Connect แล้วคัดลอก Project URL และ Publishable key (ขึ้นต้น sb_publishable_...)
   ห้ามใช้ Secret key หรือ service_role key ในเว็บไซต์
3. ตรวจว่า Supabase Realtime เปิดใช้งานอยู่ ระบบต้นแบบนี้ใช้ Broadcast/Presence จึงยังไม่ต้องสร้างตาราง SQL
4. แตก ZIP แล้วนำ index.html, style.css, app.js และ online-simulator.js ไปใส่ในโฟลเดอร์เดียวกับเว็บไซต์เดิม โดยใช้ไฟล์ทั้ง 4 ไฟล์นี้แทนไฟล์ชื่อเดียวกัน
5. เก็บโฟลเดอร์ public/ และรูปการ์ดทั้งหมดไว้เหมือนเดิม
6. Deploy โปรเจกต์ขึ้น Vercel ใหม่
7. ทั้งสองเครื่องเปิดเว็บไซต์ > Play Test > ทดลองเล่น 2 คน แล้วกรอก Project URL และ Publishable key ของโปรเจกต์เดียวกัน
8. คนแรกกด “สร้างห้องออนไลน์” แล้วส่งรหัสห้องหรือลิงก์ให้เพื่อน ส่วนเพื่อนกรอกรหัสแล้วกด “เข้าร่วมห้อง”
9. ทั้งสองฝ่ายต้องมี Deck บันทึกไว้ในเบราว์เซอร์ของตัวเองก่อนเริ่มเล่น และเลือก Deck ของตัวเองในหน้าเกม

ระบบที่ซิงก์
- สถานะออนไลน์และการเข้าห้อง
- จำนวนการ์ดใน DECK และ HAND
- การ์ดบน FIELD และ TOMB
- เทิร์นปัจจุบัน
- ซ่อนหน้าการ์ดในมือของคู่แข่งจากหน้าจอของผู้เล่นอีกฝ่าย

ข้อจำกัดสำคัญ
- นี่เป็นระบบต้นแบบสำหรับทดสอบเกม ไม่ใช่ระบบแข่งขันที่ป้องกันการโกงได้เต็มรูปแบบ รหัสห้องไม่ใช่ระบบยืนยันตัวตน และผู้ที่มีรหัสอาจพยายามเข้าห้องได้
- แม้หน้าจอจะซ่อนการ์ดในมือคู่แข่ง แต่เวอร์ชันต้นแบบฝั่งไคลเอนต์ยังไม่เหมาะกับการแข่งขันจริง ควรเพิ่ม Supabase Auth, private Realtime channels/RLS และ backend หรือ Edge Function ที่ตรวจสอบการกระทำก่อนเปิดให้สาธารณะใช้
- ระบบยังไม่คำนวณความสามารถการ์ด การต่อสู้ Counter หรือเงื่อนไขชนะโดยอัตโนมัติ
- ไม่ต้องนำ Secret key หรือ service_role key ไปใส่ในเว็บเด็ดขาด
- index.html โหลด Supabase JS จาก CDN จึงต้องเชื่อมต่ออินเทอร์เน็ต
